เวลามีโปรเจกต์ที่พร้อมขึ้นเซิร์ฟเวอร์ งานไม่ได้จบแค่ทำให้แอปรันได้ ยังมี Nginx, HTTPS, โดเมน และการอัปเดตเวอร์ชันให้ดูแลด้วย Suthep เกิดจากโจทย์นี้: ทำให้การดีพลอย Docker สำหรับโปรเจกต์ขนาดเล็กจัดการได้ง่ายขึ้น โดยไม่ต้องเริ่มตั้งค่าทุกอย่างใหม่ด้วยมือ

## รวมงานที่ต้องทำก่อนแอปพร้อมใช้งาน

Suthep เป็นเครื่องมือ CLI ที่ช่วยเชื่อมขั้นตอนดีพลอยเข้าด้วยกัน ตั้งแต่จัดการ Docker container และ Nginx reverse proxy ไปจนถึง HTTPS ผ่าน Certbot นอกจากนี้ยังรองรับหลายโดเมนหรือซับโดเมน และ health check สำหรับตรวจสอบบริการ

มุมที่น่าสนใจของโจทย์นี้คือส่วนต่าง ๆ พึ่งพากัน: แอปต้องรันใน container, Nginx ต้องส่งคำขอไปยังบริการที่ถูกต้อง และ HTTPS ต้องใช้กับโดเมนที่ตั้งไว้ ถ้าต้องจัดการแต่ละส่วนแยกกัน การเปลี่ยนค่าเพียงจุดเดียวก็อาจทำให้ต้องไล่แก้หลายไฟล์

Suthep จึงใช้ไฟล์ YAML เป็นจุดรวมการตั้งค่า เป้าหมายไม่ใช่ซ่อนการทำงานของเซิร์ฟเวอร์ แต่ทำให้ค่าที่ใช้กับโปรเจกต์อ่านและทบทวนได้ในที่เดียว วิธีนี้ยังช่วยให้การตั้งค่าเดิมนำกลับมาใช้ได้ แทนการพึ่งขั้นตอนที่จำจากการทำครั้งก่อน

การออกแบบ CLI สำหรับงานลักษณะนี้ต้องคิดถึงทั้งค่าที่ผู้ใช้ระบุและผลที่เกิดบนเซิร์ฟเวอร์ คำสั่งควรทำให้เห็นว่าโปรเจกต์ต้องการบริการแบบไหน ขณะที่การจัดการ Docker, Nginx และ Certbot เป็นรายละเอียดที่เครื่องมือช่วยประสานให้

## การอัปเดตที่ไม่ควรทำให้บริการหยุด

การปล่อยเวอร์ชันใหม่ไม่ควรทำให้ผู้ใช้เจอช่วงที่บริการเข้าไม่ได้ Suthep จึงรองรับการดีพลอยแบบ zero-downtime เพื่อช่วยให้การเปลี่ยนเวอร์ชันราบรื่นขึ้น พร้อมกับจัดการส่วนประกอบที่เกี่ยวข้องอย่าง reverse proxy และใบรับรอง HTTPS

จุดนี้ทำให้การดีพลอยไม่ใช่แค่สั่งให้ container เริ่มทำงาน แต่ต้องคำนึงถึงสถานะของบริการระหว่างเปลี่ยนเวอร์ชันด้วย health check ช่วยตรวจว่าบริการตอบสนองได้ ส่วน Nginx เป็นชั้นที่เชื่อมคำขอจากโดเมนไปยังบริการ การมองงานเหล่านี้เป็น workflow เดียวช่วยให้เห็นความสัมพันธ์ของแต่ละขั้นชัดขึ้น

## ขอบเขตที่เลือกและสิ่งที่ได้เรียนรู้

การรองรับหลายโดเมน, HTTPS, health check และการอัปเดตแบบไม่หยุดบริการทำให้เครื่องมือมีขอบเขตมากกว่าการเป็น wrapper รอบ Docker แต่การรวมความสามารถเหล่านี้ก็ต้องแลกกับการดูแลการตั้งค่าให้เข้าใจง่าย จึงเลือกใช้ YAML เป็นรูปแบบที่ประกาศสิ่งที่ต้องการอย่างชัดเจน แทนการเพิ่มขั้นตอนตั้งค่าผ่านหน้าจอหรือบริการภายนอก

บทเรียนจากโจทย์นี้คือเครื่องมือดีพลอยควรช่วยลดงานซ้ำ โดยไม่ทำให้ผู้ใช้มองไม่เห็นสิ่งที่ระบบกำลังจัดการ แนวทางที่เรียบง่ายและตรวจสอบได้สำคัญพอ ๆ กับการทำให้คำสั่งดีพลอยสั้นลง

## สิ่งที่ Suthep ตั้งใจทำ

- จัดการการดีพลอย Docker ผ่าน CLI
- ตั้งค่า Nginx reverse proxy และ HTTPS ด้วย Certbot
- รองรับหลายโดเมน health check และการดีพลอยแบบ zero-downtime
- ใช้ YAML สำหรับกำหนดค่าโปรเจกต์
